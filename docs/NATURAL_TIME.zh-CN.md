# 手动添加待办的时间理解

本次改动仅用于现有“添加待办”表单。没有新增采集入口、在线 API、依赖包或数据库迁移。原有 `extraction/dates.py` 的历史调用和测试保持独立。

## 数据流与实现

1. `temporal_grammar.py` 把中、英、德词法单元转成日历操作，再根据组合规则连接成表达式。正则只负责识别日期、数词、单位、修饰词、星期和钟点；日期结果不由整句匹配表提供。
2. `temporal_calendar.py` 解释这些操作。重复“下”对应周/月/年偏移；重复“大”修饰“后天”的基础偏移；“的”连接相对锚点。月、年运算按目标月份合法天数截断，星期按周一开始的日历周计算。时间合法性通过 IANA 时区双向转换检查。
3. `temporal.py` 分析表达式前后的截止、开始、否定、修正和条件关系。多个任务动作无法确定主次时保留候选，只创建用户提交的一项任务。唯一明确截止关系优先于背景日期。
4. `quick_add.py` 只移除已可靠选中的时间片段及紧邻的时间介词，保留其他时间上下文。未确认表达、条件句、仅时间、未知表达保留原句，避免丢失信息。
5. `/tasks/quick-parse` 保留原返回字段，增加 `temporal` 和 `timezone`。原 `due_date` / `due_time` 只返回可自动填写的值。

`temporal` 包含状态、精度、标准日期与时间、原表达、置信度、确认标志、原因代码和带原文位置的候选。置信度是规则等级，不是统计校准的概率。候选可以包含日期区间；区间端点不会被隐式保存成截止日。

状态区分 `absent`、`resolved`、`inferred`、`unresolved`、`urgency`；精度区分 `none`、`date`、`datetime`、`range`、`time`、`period`。

`SemanticProvider` 是可选扩展接口，接收完整句子、参考时间和时区，返回原文位置及日历操作。当前没有接入 LLM。扩展候选也必须通过日历合法性验证，且始终需要确认；扩展失败不影响无日期创建。

## 产品规则

参考时刻使用可注入的服务端时钟，时区由浏览器本地 IANA 时区提供，并随任务保存；未传时区的旧客户端沿用应用设置。提交时刷新解析，或复用尚未完成的同一请求，防止表单跨午夜后保存过期预览。

以慕尼黑 2026-10-21 为参考：

| 输入 | 行为 |
| --- | --- |
| 后天晚上8点交作业 | 标题“交作业”，10-23 20:00 |
| 明早交作业 | 10-22，时间空白，提示只指定大致时段 |
| 大大大大大大大后天 | 候选 10-30，需点击确认 |
| 下下下周五 | 11-13 |
| 三周后的周二 | 三周后所在日历周的周二，即 11-10 |
| 后天的后一天 | 10-24 |
| 明天的下周三 | 10-28 |
| 明年三月初 | 2027-03-01 至 03-10 的建议范围，不自动选日期 |
| 两周以内 | 10-21 至 11-04，不自动选日期 |
| next Friday at 5pm | 保留最近一次周五及下个日历周周五的候选 |
| due nächsten Montag 23:59 | 最近周一与下个日历周周一一致，可自动填写 |
| 周五考试，周三之前复习完 | 选择周三截止；标题保留周五考试的背景 |
| 不是周五，是下周一交作业 | 选择下周一；去除被纠正的日期措辞 |
| 如果周五没完成，就周日处理 | 两个候选，要求用户选择 |
| submit report by Oct 20 5pm | 今年已过期与下一年的候选，不自动跨年 |
| 整理2025年的财务报表 | 标题完整保留，不生成截止日期 |

“月初”目前是 1–10 日的建议范围；“end of next week”保留周五至周日的范围。这些是公开的解释约定，不声称用户指定了准确端点。“ASAP”和“尽量早点”只有紧急程度，不产生日期。

工作日只排除周六和周日，并明确提示未使用地区法定节假日日历。不存在的日期、DST 跳过的钟点、DST 重复的钟点不会直接填入或保存成确定瞬间。当前任务模型没有夏令时 fold 字段，因此重复钟点需要换成明确钟点或只保存日期。

## 表单状态

输入防抖 250 ms，中文输入法组合期间暂停请求。每次实际输入变化立即提升版本；旧结果、清空后的结果和卸载后的结果都不能更新界面。解析等待上限为 4 秒，失败可以按原句无日期保存。

日期和时间分别保持手动覆盖，清空也是用户决定。确认候选日期不会覆盖另行手动修改的时间。保存期间锁定表单，避免保存快照与可见输入变化相互竞争。

未确认候选不会持久化为截止时间。确定解析、候选确认和手动覆盖的来源写入现有创建事件的 `time_resolution` 字段，取值 `parsed`、`confirmed`、`overridden`；普通手动创建为 `explicit`。没有修改任务表结构。

## 测试与边界

`test_temporal.py` 使用固定参考时刻，覆盖三种语言和混合输入、递归修饰、上下文、年份推断、过去截止、非法日期、闰年、DST、标题保护及 API 时区验证。生成式循环检验重复修饰词、偏移组合、连续周偏移、跨月合法性、工作日和多时区跨年一致性。

`useQuickTaskParse.test.tsx` 控制时钟和 Promise 完成顺序，覆盖防抖、输入法、旧请求、A→B→A、倒序返回、立即提交、超时、清空与卸载。`TaskQuickEntry.test.tsx` 覆盖表单覆盖优先级、候选确认、无日期保存和时间精度。现有添加、编辑、快捷键和 API 测试继续运行。

仍不保证识别任意自然语言、错别字或跨句指代。未支持的事件锚点、含糊日期关系、非本地时区写法、复杂条件句保留原文和可用候选，不靠猜测补全。明显日期格式或已知时间提示无法解析时给出简短说明；没有可识别时间信号的文本可作为普通待办保存。
