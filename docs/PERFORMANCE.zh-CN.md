# 时间与空间复杂度优化记录

## 2026-10-25：180 Hz 实屏上的折射合成开销

上一轮只减少布局读取，未解决滚动掉帧。本轮使用独立数据目录的真实 WebView2 窗口复现：“今天”滚动时约 65–100 次帧回调/秒，硬件加速正常。Chromium 追踪中 `MainFrame.Draw` 平均约 7.0 ms，主要时间位于合成帧提交，超过 180 Hz 的 5.56 ms 帧预算。

修复保留 CSS、完整位移图分辨率、折射数学、色彩居中和动画。Worker 将具有平坦中心的位移图编码为四个角、四条边和中性填充：仅当逐像素验证相同的行/列与中性中心都成立时才合并；否则保持整图。文字放大的液态选择透镜也保持整图。边缘保留一个像素重叠，降低分块边界的亚像素裁切影响。浏览器不再为这些面板反复提交大块重复像素。Worker 不可用时保留原来的整图回退。

本机 NVIDIA RTX 4060 Laptop GPU、WebView2 155.0.4283.62、180 Hz 屏幕、125% 缩放：普通窗口“今天”滚动约 179.8 次/秒；最大化视口 2048×1082 CSS 像素、36 条额外测试任务、1518 px 滚动范围，复测约 174–180 次/秒。一次包含滚动和页面切换的记录分别为 174.27 / 178.81 次/秒，P95 间隔为 5.7 / 6.0 ms；仍存在 44.4 / 27.8 ms 的偶发长帧。修复后的追踪中 `MainFrame.Draw` 平均约 1.13 ms。追踪有额外开销，不与未开启追踪的帧回调频率混为一谈。

这些是浏览器帧回调与合成追踪指标，不是显示器扫描输出的逐帧测量，也不保证所有数据量和硬件下恒定 180 FPS。深浅色截图与重建整图对比的最大平均单通道差异低于 0.0004/255；分块边缘存在极少量抗锯齿差异，不能称为截图逐像素完全相同。回归逐字节验证六组原始位移图的无损重建，覆盖非重复图回退、Worker 结果安装、尺寸改变和清理。

可在独立测试实例上复测（脚本只操作滚动与导航，不改任务数据；页面需要有足够内容才能测到滚动）：

```powershell
node scripts/desktop-check/refresh-rate.mjs 9234 build/refresh-check/results.json
```

## 2026-10-25：保持外观的玻璃效果调度优化

保留现有 CSS、折射参数、玻璃高光和动画。选中项或弹出按钮透镜发生变化时，布局事件携带实际变化的元素，玻璃引擎只测量这些透镜，不再同步读取整页卡片的尺寸和计算样式。局部更新不会取消已经排队的全局发现任务。

普通任务文本更新不再触发玻璃、选中项和弹出按钮引擎的无关全页扫描；透镜新增/删除、控件内部文本替换和 ResizeObserver 尺寸变化仍正常处理。

回归用例放置 40 个玻璃面板：更新单个选中透镜并修改任务文本后，无关面板尺寸读取为 0 次；尺寸观察器触发后仍测量全部面板，新插入面板仍生成折射滤镜。14 项相关交互测试、TypeScript、修改文件的 ESLint 及生产构建通过。这是布局工作量验证，不代表已经测得当前显示器的最高刷新率；本轮独立浏览器渲染测量因启动操作被执行策略拦截而未完成。

## 2026-10-25：日历冲突查询

在此前优化基础上，本轮减少日历冲突查询中的重复扫描与无关数据读取：

| 路径 | 修改前 | 修改后 |
| --- | --- | --- |
| 下一个空闲时段 | 每次推迟开始时间都扫描全部 N 个忙碌区间，最坏 `O(N²)` | 预计算含缓冲的区间边界，排序后单次扫描，`O(N log N)`；额外空间仍为 `O(N)` |
| 选择最新且覆盖请求时间的缓存窗口 | 加载所有候选窗口的完整事件 JSON，并保留所有覆盖窗口 | 每批 256 条流式比较元数据，只加载最终选中窗口的事件 JSON；Python 内存为固定批次元数据加一个窗口的事件，仍需扫描候选元数据 |
| 保存 Google 事件缓冲后返回结果 | 读取全部 B 条缓冲记录，Python 时间、空间均为 `O(B)` | 按主键读取当前事件和所属系列的最多两条记录，返回阶段 Python 时间、空间为 `O(1)` |

空闲时段仍遵循五分钟向上取整、包含前后缓冲、当天结束前完成以及无冲突时不提供建议的规则；不会原地排序调用方的事件列表。缓存窗口仍按各自时区精确判断覆盖范围，并保留同步时间相同时的原有选择顺序。

本机合成基准：同一天 250 个连续的五分钟忙碌区间，寻找五分钟空闲时段。直接调用函数，预热后取 7 次中位数，修改前 **29.219 ms**，修改后 **0.260 ms**。这是连续冲突场景的函数级测量，不代表完整接口或普通日程的固定提速。

新增回归将 300 组固定随机种子的日程与逐个五分钟枚举的结果对比；检查 250 个连续区间的边界只各读取一次；使用 300 个历史窗口与一个时区不覆盖的较新窗口，验证只加载最终选中的一个完整 ORM 窗口。数据库内部内存不计入上述 Python 空间界限。

验证：后端全量 446 项测试通过；修改文件的 Ruff 检查及格式检查、服务模块 Mypy 检查通过。

## 2026-10-22：任务列表、首页及关联数据

2026-10-22，在本轮修改前后的同一工作副本上检查、优化并验证。接口字段、筛选条件、时区及夏令时计算沿用原有规则。

任务列表原先加载全部匹配任务及其来源、日历关系，生成全部摘要，再排序和分页。现在先选择需要返回的 ID，最后只加载当前页的完整摘要：

| 路径 | 原有开销 | 本轮改动及复杂度 |
| --- | --- | --- |
| 截止时间、优先级、紧急程度排序；带紧急程度筛选的时间戳排序 | 完整摘要排序 `O(N log N)`，内存随全部匹配任务及关系增长 | 每批 256 条读取排序字段，使用堆保留前 K 条；筛选及选择 `O(N log(K + 1))`，排序缓冲 `O(min(N, K) + 256)`；仅当前页生成完整摘要 |
| 不带紧急程度筛选的创建、更新、发现时间排序 | Python 加载并排序全部摘要 | SQL 对 ID 排序、分页并单独计数；Python 只加载当前页，内存 `O(P)`，另加当前页来源等关联数据 |
| 首页分组及待关注任务 | 加载所有任务、生成摘要、对完整分组排序 | 单次流式扫描活动任务，每个分组保留固定数量；Python 选择阶段 `O(N)`，最多加载 41 个不同任务的完整摘要；计数和最近完成任务交给 SQL |
| 日历中判断任务是否已有工作时段 | 每个任务扫描全部工作时段，最坏 `O(T × B)` | 一次构建任务 ID 集合，匹配阶段 `O(T + B)`，额外集合空间 `O(B)`；任务查询只读取六个所需字段 |
| 任务详情中的相关任务 | 每个相关任务单独查询 | 一次联结读取全部相关任务，保留方向和回收站过滤规则 |
| 计时器关联任务 | 每个不同的关联任务产生额外查询 | 一次联结批量读取任务 ID、标题和删除时间，关联任务查询次数不随倒计时数量增长 |
| 未读提醒、导入数据数量、今日专注统计、托盘倒计时数量 | 把 ID 或完整记录加载后计数、求和 | 使用 SQL `COUNT` / `SUM`，Python 聚合结果内存 `O(1)` |
| 批量标记提醒已读 | 为每条提醒创建 ORM 对象并修改 | 一条 SQL `UPDATE`，不加载提醒对象 |
| 列表消失动画 | 对每个消失条目重复查找、切片、插入 | 顺序扫描确定锚点，按锚点分组合并；`O(N旧 + N新 + G)`，包含输出的空间 `O(N新 + G)` |
| 已完成条目的界面状态清理 | 对每个待清理 ID 扫描当前列表，`O(L × N)` | 预先构建状态映射，时间 `O(L + N)`，额外空间 `O(N)` |

N 为匹配任务数，P 为页大小，K 为 `offset + limit`；T 为日历任务数，B 为工作时段数，G 为动画保留条目数，L 为待清理状态数。

数据库计数、排序和更新仍有相应的数据访问成本，上表的 Python 内存界限不包含 SQLite 内部内存和返回结果的可变长关联内容。深分页时 K 会增大；日历仍需返回可见事件和未安排任务，因此整个日历接口的内存仍随数据量增长。倒计时完整列表仍需排序，时间复杂度仍为 `O(C log C)`。

本机合成数据基准：10,000 条任务（每条约 1 KiB 备注、包含多个时区），10,000 条通知、2,500 个工作时段、500 个各自关联不同任务的已完成倒计时。每项先预热，耗时取三次中位数，内存取三次 Python `tracemalloc` 峰值的最大值；耗时和内存分别测量。

| 操作 | 修改前耗时 | 修改后耗时 | 修改前 Python 峰值 | 修改后 Python 峰值 |
| --- | ---: | ---: | ---: | ---: |
| 截止时间排序，返回 50 条任务 | 542.41 ms | 60.81 ms | 71.14 MiB | 0.60 MiB |
| 创建时间排序，返回 50 条任务 | 538.73 ms | 14.95 ms | 71.14 MiB | 0.47 MiB |
| 首页 | 581.57 ms | 87.85 ms | 75.53 MiB | 0.48 MiB |
| 月历 | 1882.29 ms | 84.70 ms | 56.59 MiB | 14.01 MiB |
| 未读提醒计数 | 5.39 ms | 1.26 ms | 1.72 MiB | 0.03 MiB |
| 500 个倒计时概览 | 61.62 ms | 10.96 ms | 3.77 MiB | 2.57 MiB |

这些数值用于比较本轮修改，不代表所有电脑或真实数据的固定响应时间。基准直接调用服务和路由函数，不包含 HTTP 传输、浏览器渲染、Google 网络请求，也未测量 SQLite 原生内存或整个进程的峰值。
