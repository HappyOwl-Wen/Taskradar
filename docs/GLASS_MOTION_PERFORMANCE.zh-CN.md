# 玻璃动画性能记录

2026-10-24。改动前存档：`ui-before-smooth-performance-20261024`（`ce8d388`）。

## 修复内容与原因

- 选择框的原边框以前留在按钮上，装饰透镜独自形变。现在边框、底色、阴影和焦点光环由同一玻璃层绘制，按钮保留原点击区域。
- 顶部搜索输入移除内框、独立底色和阴影，使用顶栏的玻璃材质；聚焦时显示轻量外光环。
- DropdownMenu、Popover、Select、通知、状态浮层和提示共用 280 ms 单调减速展开，从实际触发按钮方向起步。选中层共用 240 ms 平滑移动。均无过冲、反向回弹或固定帧率计时器。
- 侧栏逐帧改变宽度会不断触发布局与贴图重建。现在先更新一次布局，再用 200 ms Web Animations 变换移动工作区、伸缩独立侧栏材质；页面文字不缩放。快速反向操作能续接并清理旧动画。
- 页面容器的缩放和透明度动画会把大量背景滤镜放进同一个动画分组。现在只淡入标题，保留导航选中层的运动。
- 光学像素计算、Canvas 绘制和 PNG 编码移到 Worker/OffscreenCanvas。相同尺寸请求去重，最多缓存 96 份；无 Worker 时使用最大边 128 px 的小贴图回退。
- 集中读取布局后再写样式，忽略光学引擎自身的 class 变化，取消大面板逐指针帧更新高光，移除额外模糊和饱和度滤镜通道。SVG 背景折射持续保留。

## 测量范围

Windows 读取的显示模式为 2560 × 1440、180 Hz，显卡 AMD Radeon 780M。
测量使用 Chromium 内嵌浏览器，页面视口 1280 × 720，隔离的 `calendar-check` 演示数据库与 Fake Calendar。
真实任务、账号和主服务配置未参与写入。

每个样本观察 2.6 秒原生 `requestAnimationFrame` 回调间隔，并使用 `PerformanceObserver(longtask)` 记录超过 50 ms 的主线程长任务。
先记录静止基准，再执行四次侧栏收起/展开；切页样本按“番茄钟 → 今天 → 全部任务 → 今天”执行，测量前先预热这些路由。
自动操作间隙也计入采样，帧数不是持续动画期间的平均 FPS。短样本会受浏览器和系统其他工作影响。

## 高刷新率结论与限制

动画使用浏览器合成时间线，不设置 60/120 FPS 上限；中位回调间隔约 5.6 ms，与 180 Hz 刷新周期相符。
原先侧栏操作中明显阻塞主线程的问题已消除。

**这组结果不能宣称“全程锁定 180 FPS”。** P95 仍有约 11.1 ms 的间隔，侧栏压力样本最长 39 ms，仍存在合成掉帧。
回调间隔也不等同于屏幕实际呈现帧的测量；当前验证不包含 GPU 呈现追踪或桌面 WebView2 的独立逐帧记录。
该限制明确保留，不能用中位间隔替代全程满刷新率的证据。

- 前端 48 个文件、244 项测试通过；ESLint 和 TypeScript/生产构建通过。
- 覆盖 Worker 请求去重、缓存边界、失败回退和卸载后结果丢弃。
- 覆盖侧栏动画中断、动画结束后的样式清理、减少动画偏好、无 Web Animations API 回退。
- 覆盖真实 Radix 菜单的键盘/鼠标打开、Esc 焦点恢复、选择提交和透镜清理，以及导航选中层尺寸变化。
